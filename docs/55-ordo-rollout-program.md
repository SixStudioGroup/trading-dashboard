# Ordo Rollout Program

Version: 0.1
Status: Active rollout structure
Owner: Founder / CTO

## Purpose

This document defines the rollout structure for the next phase of the ZenCloudAU founder-incubator estate.

The estate has moved from rapid creation into ordered expansion. The next phase is not another uncontrolled build sprint. The next phase is a sequenced overhaul using the new model: Roman semantic architecture, Imperium venture judgement, Velocity Vibes delivery discipline, repository governance, and agent-specific execution.

## Operating posture

The estate is now treated as a digital republic of product institutions.

Each product line must have a proper identity, category, repository boundary, deployment path, and venture role before major build work continues.

Claude and Codex should no longer receive broad prompts. They should receive narrow release commands with acceptance criteria.

## Rollout sequence

| Phase | Name | Purpose | Primary output | Executor |
|---|---|---|---|---|
| 0 | Status Lock | Freeze uncontrolled expansion and record current state | Estate baseline | ChatGPT / Founder |
| 1 | Taxonomia | Classify the estate into domains, categories, and future venture lines | Estate taxonomy and repo classification | ChatGPT |
| 2 | Nomenclatura | Define Latin/Roman naming doctrine and candidate names | Naming doctrine and name registry | ChatGPT |
| 3 | Disciplina | Install repository and agent governance | Governance docs and AGENTS.md files | ChatGPT / Claude |
| 4 | Custos | Reframe Valour as guided AI presence rather than workflow tool | UX doctrine and focused build brief | ChatGPT / Claude |

| 7 | Imperium Review | Assess each venture candidate through the Imperium canon | Build / hold / spin-out decisions | Founder / ChatGPT |

## Phase 0: Status Lock

Phase 0 records what exists and prevents new uncontrolled creation.

Rules:

- No new product ideas become repos without classification.
- No existing repo absorbs another product line.
- No deployment changes without ownership clarity.
- No public rename without naming doctrine.
- No app overhaul without release scope.

Exit condition: estate baseline is documented.

## Phase 1: Taxonomia

Taxonomia classifies the estate.

It answers:

- What is this asset?
- What category does it belong to?
- Is it a product, framework, tool, doctrine, learning asset, creative IP, or venture candidate?
- What repo owns it?
- What must it not become?

Outputs:

- Founder Incubator Estate Architecture
- Repo classification matrix
- Category constraints
- Spin-out rules

Status: started through `docs/53-founder-incubator-estate-architecture.md`.

## Phase 2: Nomenclatura

Nomenclatura defines the Roman/Latin naming system.

It will define:

- public naming principles,
- internal naming principles,
- product naming rules,
- lifecycle terminology,
- category naming patterns,
- candidate Latin names for each product line,
- rules for when repo names can be changed.

Modern startup terms such as pilot, MVP, proof of concept, copilot, assistant, dashboard, and generator should be replaced over time where appropriate.

This does not mean making the UX obscure. Latin identities must always be paired with plain English explanation.

## Phase 3: Disciplina

Disciplina installs repo-level governance.

Each active repo should receive a local `AGENTS.md` or equivalent guardrail file explaining:

- what the repo owns,
- what it must not own,
- deployment surface,
- allowed changes,
- stop conditions,
- public/private terminology rules.

Priority repos:

- `ordo-animi`
- `velocity-architecture`
- `sa-artefact-generator`
- `executive-fast-track`
- `trading-dashboard`
- `obsidian-vault`
- `vallum-engine`

## Phase 4: Custos

Custos is the next product experience phase for Valour.

The goal is to move from visible workflow to guided AI presence.

Valour should not feel like a form or workflow system. It should feel like Custos is guiding the user through a difficult leadership moment.

Scope:

- persistent guide presence,
- context-aware stage guidance,
- plain-language entry point,
- reduced workflow-heavy language,
- pattern report as destination,
- live guidance rather than passive generated panels.

## Phase 5: Exploratio

Exploratio replaces the language of pilot/proof of concept for internal doctrine.

Exploratio means live exploration, validation, and field testing.

For Valour, this means:

- user can land cold,
- understand the promise,
- describe a leadership situation,
- receive guided preparation,
- rehearse a hard question,
- refine language,
- complete a report,
- export or retain the result.

## Phase 6: Productio

Productio packages each product line into a proper app, product, or venture candidate.

This includes:

- product charter,
- identity,
- repo boundary,
- deployment surface,
- user and buyer,
- commercial path,
- roadmap,
- governance.

No product line should be treated as commercial until this package exists.

## Phase 7: Imperium Review

Imperium Review determines whether a product line deserves continued investment, a hold state, or spin-out.

Each candidate is assessed through:

- Incendium,
- Machina,
- Pecunia,
- Ecosystema,
- Regio,
- Impactus,
- Unicum,
- Mandatum.

## Claude command discipline

Claude should receive one release slice at a time.

A valid Claude command includes:

- target repo,
- phase,
- objective,
- files or areas likely affected,
- explicit exclusions,
- acceptance criteria,
- expected completion report.

Claude should not receive broad instructions such as `overhaul the whole ecosystem` or `make it better`.

## Codex command discipline

Codex should receive precision tasks.

A valid Codex task includes:

- one bug,
- one component,
- one refactor,
- one typing issue,
- one failing behaviour,
- one expected output.

Codex should not receive brand, doctrine, or whole-product ambiguity.

## ChatGPT role

ChatGPT owns the architecture and product control layer:

- doctrine,
- taxonomy,
- release design,
- task shaping,
- UX strategy,
- governance,
- review synthesis,
- next-command construction.

## Founder role

The Founder / CTO owns:

- vision,
- taste,
- final naming decisions,
- commercial judgement,
- product truth,
- live validation,
- investor/advisor framing.
