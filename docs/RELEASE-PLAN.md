# Release Plan

## Release Objective

Stabilise SixQuant Trading Dashboard as a disciplined manual trading terminal before expanding feature scope.

The immediate goal is not feature expansion. The immediate goal is workflow maturity.

## Release 1.0 Candidate Scope

The user must be able to:

- Open the dashboard and immediately understand live versus fallback state.
- Review ranked opportunities.
- Select a single opportunity for deeper analysis.
- Understand the trade thesis.
- Understand risk and invalidation.
- Unlock external execution only after analysis is complete.
- Record the outcome.
- Review the session later.

## UX Priorities

The current dashboard exposes too many competing surfaces simultaneously.

Release 1.0 should:

- Reduce visual overload.
- Strengthen workflow hierarchy.
- Keep execution locked until analysis completes.
- Improve decision confidence.
- Reduce non-essential data exposure.

## Product Risks

The largest product risk is premature expansion.

The dashboard should not become:

- A social trading app.
- An automated trading bot.
- A broker.
- A prediction engine.
- A signal spam dashboard.

The product should remain focused on disciplined manual execution.

## Acceptance Criteria

Release 1.0 is complete when:

- The workflow is understandable within minutes.
- The dashboard clearly communicates trust state.
- The user can complete the full trading loop without confusion.
- Manual holdings operate consistently.
- Execution gating works correctly.
- Documentation reflects actual product behaviour.
- The interface feels calm rather than chaotic.

## Post-Release Direction

After Release 1.0, future work should prioritise:

- Journal quality
- Review systems
- Performance tracking
- Signal prioritisation
- Trade discipline metrics

Not feature count.
