# Archivum Operator Runbook

## Establish an engagement

Create a new private repository from the approved Archivum structure. Confirm repository owner, client owner, access list, classification, start date, expected close date, and retention review date. Replace all placeholders before client access is granted.

## Operate the archive

Use the client home page as the table of contents. Store artefacts in the correct domain folder. Use Markdown and JSON as canonical portable formats. Keep rendered files in the exports area. Record source product, version, status, classification, and owner for controlled artefacts.

Review access whenever team membership changes. Remove temporary working files and avoid committing local exports, credentials, or unrelated material.

## Review before handover

Check the artefact index, final versions, links, classifications, approvals, and unresolved items. Move superseded material into the archive area or mark it clearly. Confirm the final export package can be opened without the originating application.

## Handover

Provide the agreed repository archive and rendered outputs. Record recipient, delivery date, format, outstanding items, and acknowledgement.

## Retain

Remove unnecessary collaborators. Keep the repo private and stable. Review it on the agreed retention date.

## Close

Archive or delete according to the approved instruction. Record the closure outcome in the relevant governance record outside the deleted repository where necessary.

## Escalation

Stop and seek Founder / CTO approval if the engagement requires executable code, automated writes, cloud credentials, highly sensitive information, external integrations, or a change to the one-client-one-repo boundary.
