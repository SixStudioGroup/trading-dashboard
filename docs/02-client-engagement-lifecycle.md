# Client Engagement Lifecycle

Archivum uses six lifecycle states.

| Latin state | Plain English | Required outcome |
|---|---|---|
| Constitutio | Establish | Private repo created, owner confirmed, access approved, classification set |
| Operatio | Operate | Artefacts created, reviewed, versioned, and indexed |
| Recognitio | Review | Completeness, ownership, classification, and quality checked |
| Traditio | Handover | Final package delivered and receipt recorded |
| Retentio | Retain | Repo locked down for the agreed retention period |
| Clausura | Close | Repo archived or deleted under written instruction |

## Constitutio

Create one private repo for one client or engagement. Copy only approved templates. Add named collaborators using least privilege. Record the engagement owner, client owner, start date, expected close date, default retention period, and approved information classification.

## Operatio

Use the client home page as the table of contents. Store artefacts in the correct domain folder. Each controlled artefact should have a manifest or clear metadata block. Do not store credentials, unrelated client data, or temporary exports that are no longer needed.

## Recognitio

Before sign-off, review completeness, broken links, duplicate artefacts, classification, decisions, approvals, and final versions. Resolve draft or superseded material.

## Traditio

Provide the client with an agreed export of the full repository and any rendered deliverables. Record the handover date, format, recipient, and unresolved items.

## Retentio

Remove unnecessary collaborators. Make the repo read-only where practical. Keep it private. Review retention on the agreed date.

## Clausura

Archive or delete according to contract and client instruction. Record the closure decision outside the deleted repo if deletion evidence must be retained.
