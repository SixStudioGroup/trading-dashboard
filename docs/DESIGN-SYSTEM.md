# Design System

## Colour Standard

The trading dashboard uses a restrained execution-terminal palette. The colour system should support focus, hierarchy, and risk awareness rather than visual excitement.

## Core Tokens

Primary action: ZenCloud blue.

Background: cool slate.

Surface: white.

Raised surface: pale slate.

Border: slate line.

Text: dark navy slate.

Muted text: slate grey.

Positive state: green.

Negative state: red.

Caution state: amber.

Information state: cyan.

## Usage Rules

Blue is reserved for navigation, primary actions, selected rows, active tabs, and execution-ready states.

Green is reserved for confirmed positive movement, profitable state, or favourable signal state.

Red is reserved for loss, risk, invalidation, delete actions, and sell-risk states.

Amber is reserved for caution, fallback, incomplete confirmation, and watch states.

Cyan is reserved for neutral live-data or information states.

Avoid decorative colour. Colour should always communicate state, priority, or user action.

## Workflow Design Principle

The default dashboard must read as a guided trading loop:

Scan.
Analyse.
Decide.
Execute externally.
Record.
Review.

Secondary surfaces should not compete with the active decision. Portfolio, movers, market attention, and review should remain subordinate unless selected by the user.

## Release 1.0 UX Rule

The dashboard should feel calm, structured, and deliberate. It should not feel like a casino, social trading feed, or generic analytics wall.
