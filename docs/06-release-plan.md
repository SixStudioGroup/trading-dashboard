# Archivum Release Plan

Archivum is released through controlled capability layers.

| Release | Purpose | Primary executor | Exit condition |
|---|---|---|---|
| v0.1 Fundamentum | Manual secure archive foundation | ChatGPT | Doctrine, security, lifecycle, Exportum, templates and kanban complete |
| v0.2 Recognitio | Precision consistency review | Codex | Links, schemas, examples and template fields validated |
| v0.3 Constitutio | Reusable client-repo scaffold | Claude | Template can create a clean client archive without manual restructuring |
| v0.4 Nexus | Controlled product handoff | Claude and Codex | One estate product exports a canonical package into a test archive |
| v0.5 Custodia | Security hardening and operator controls | Codex | Permissions, failure handling and audit requirements validated |
| v1.0 Traditio | Client-ready operating pattern | Founder / CTO | Simulated engagement completes from establishment through handover |

## MVP

The minimum viable release is v0.1. It works manually and securely without code, dependencies, CI, APIs, or deployment.

## MLP

The minimum lovable release is v0.3. An operator can create a polished client archive, navigate it from a clear home page, and complete handover without understanding Git internals.

## Release discipline

No automation begins before the manual archive pattern has been used end to end. No integration receives production credentials before a security design and explicit Founder / CTO approval. No release may introduce mixed-client storage.
