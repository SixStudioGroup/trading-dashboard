Shared User Guide

ZenCloud is a manual multi-asset trading operating portal. Crypto and stocks are separate workspaces, while journal, reports, privacy mode, and value hiding are shared.

Getting Started

What this portal is and how to run a session

What ZenCloud Is

Decision support, not automation

ZenCloud is a manual multi-asset trading operating portal. It turns workspace data, manual positions, and journal records into a compact operating system. Every component is read-only or manually updated — it is not an exchange, not a broker, not an auto-trader, and not a prediction engine.

The Crypto Workspace uses the existing public crypto feed for market scan and planning. The Stocks Workspace is separate and may use static or demo stock data until a safe source is added. Journal entries, watchlist, positions, and session state are stored locally in your browser when Private Local Mode is active.

Workspace Architecture

Crypto and stocks stay separated

Crypto Workspace: uses existing crypto market data for market scan and planning. CoinSpot is execution only and remains behind the existing analysis and checklist handoff rules.

Stocks Workspace: uses ticker, position, broker, Best Setup, Risk Panel, and Agent Consensus terminology for stock scan and planning. It does not appear inside the crypto Opportunity Queue and broker execution is a placeholder only.

Shared Journal and Shared Reports: records carry an assetClass value of crypto or stock.

Core Operating Rule

Keep execution separate

Use ZenCloud to decide, plan, record, and review. Use CoinSpot only for crypto execution after analysis. For stocks, the Broker Handoff panel is a placeholder only and does not connect to, open, or pre-fill any broker.

ZenCloud never creates guessed execution links, pre-fills order forms, or connects to exchange or broker APIs. The execution boundary is always manual.

Daily Trading Workflow

Run the same sequence every session — do not skip steps

Scan → Analyse → Plan → Execute externally → Update Position → Journal → Review

  1. Choose the workspace: Crypto Workspace for crypto, Stocks Workspace for stocks.
  2. Scan the relevant Opportunity Queue. Crypto and stocks are ranked separately.
  3. Select one asset or ticker and complete Asset Analysis before planning.
  4. Create or confirm a trade plan with signal state, reason, entry trigger, invalidation, intended size, and notes.
  5. Execute externally only after the ZenCloud plan exists. CoinSpot is for crypto execution. Stock broker execution is not connected.
  6. Update Holdings or Positions immediately after the external trade confirms.
  7. Journal the trade with asset class, reason, invalidation, result, behaviour review, and notes.
  8. Review Reports, Market Logs, and Alerts at the end of the session.

Scanning

Entry point for every session — start here, not with market news

Opportunity Queue

Primary scan surface

The Opportunity Queue ranks assets from the scoring engine by signal state and momentum. It is the fastest answer to what currently matters. Open it first, every session.

Click Analyse on any row to load that asset into the Asset Analysis panel.

Breakout Watch Sell Risk Volume Spike No Action

Crypto uses existing crypto movement and liquidity labels. Stocks use stock-specific inputs: 1D movement, 5D movement, relative volume, sector, market regime, and risk state. No Action means neutral or insufficient data.

Best Swing Mover

One short-to-medium-term candidate

This box highlights one liquid, non-high-risk candidate when current state supports further analysis. Criteria: $100M+ volume, not in Sell Risk state, positive momentum.

It never opens CoinSpot directly. Treat it as a starting point — not a recommendation. Click Analyse to load it into Asset Analysis before acting.

Market Regime

Context, not an override

Market Regime summarises broad liquidity, volatility, dominance, and rotation context where available. Read it for situational awareness.

It does not override the Opportunity Queue, trade plan, or risk controls. A constructive regime does not override a Sell Risk state.

Market Attention

Secondary discovery only

Market Attention groups Trending, Top Gainers, Top Losers, Most Visited, and Recently Added assets. Use these lists to discover assets, not to trade them directly.

Assets not supported by CoinSpot remain Watch only regardless of signal state. Always route discovery findings through the Opportunity Queue and Asset Analysis before planning a trade.

Analysis & Planning

Work one asset at a time — complete each step before moving to execution

Asset Analysis

Inspect before acting

Asset Analysis isolates one asset with signal state, market movement, volume context, invalidation level, position sizing, and the execution handoff gate.

On desktop, the panel is sticky — it stays visible while you scroll the rest of the dashboard. On smaller screens it falls inline. Work through it top to bottom: signal → agents → plan → size → checklist → handoff.

Agent Consensus

Four deterministic rule checks

Four agents evaluate the selected asset independently:

  • Momentum — trend direction and 1hr/24hr momentum.
  • Liquidity — 24hr volume against suitability thresholds ($100M+ suitable, $25M–$100M caution, below $25M avoid).
  • Risk — 24hr and 1hr move magnitude against risk bands.
  • Portfolio — whether the asset is already held.

Each returns Support, Watch, Reject, or Insufficient Data. Consensus informs but does not unlock execution by itself — the checklist gate controls that.

Execution Checklist Gate

Five checks must complete before handoff unlocks

The CoinSpot handoff button stays locked until you manually confirm five checklist items in Asset Analysis. This is intentional — it forces review before execution.

The checklist items cover: signal validity, agent consensus review, invalidation level set, position size calculated, and trade plan saved. Progress is shown as X / 5 checks above the handoff button.

If you do not complete the checklist, the handoff button does not activate. There is no way to bypass this gate within ZenCloud.

Watch Queue

Assets saved from analysis for monitoring

Watch Queue stores assets added from Asset Analysis. Each entry records: reason watched, signal at watch time, current signal, watch timestamp, and whether signal state has improved, weakened, or stayed neutral since being added.

Use it to track assets that are close to a Breakout but not yet ready. Return to Asset Analysis when signal state improves.

Trade Plan

Required before handoff

Create a plan with: asset, signal state, reason, entry trigger, invalidation level, review time, intended size, and notes. A saved plan can be added directly to the Trade Journal.

Do not proceed to the external venue without a completed plan. If the idea cannot be articulated in the plan fields, it is not ready for external execution.

Risk Per Trade

Define max loss before handoff

Input: account value, risk percentage, entry price, and invalidation price. Output: max risk amount in AUD, implied position size, and estimated units.

Define risk before sizing. The sizing helper depends on invalidation being set first — a trade plan without an invalidation level cannot produce a valid risk calculation.

Position Size Helper

Sizing context, not an order

The helper estimates intended allocation, risk amount, units, and portfolio weight after the trade. It is informational only — it does not send orders, does not pre-fill CoinSpot, and does not connect to any exchange.

CoinSpot Execution Handoff

External execution only — after checklist completes

The handoff button activates only when all five checklist items are confirmed. It opens CoinSpot so you can place the actual trade manually.

CoinSpot is used for: placing the trade, checking real account balance, and confirming completed transactions. ZenCloud never creates guessed CoinSpot links or pre-configured order URLs.

Broker Handoff Placeholder

Stocks remain manually planned and externally executed

The Stocks Workspace records ticker analysis, stock agent consensus, risk panel values, and a stock trade plan. Broker execution is not connected.

ZenCloud does not add broker links, does not guess broker URLs, does not open broker order forms, and does not pre-fill stock orders. The placeholder exists to preserve the workflow boundary: ZenCloud decides, the external broker executes, ZenCloud records and reviews.

Track & Review

Update holdings immediately after execution — journal every trade

Manage Holdings

Manual portfolio tracking — local storage only

Update crypto holdings or stock positions after external trades confirm. Crypto holdings and stock positions are separate records and are stored only in the current browser when Private Local Mode is active.

Important: Private Local records exist on this device and browser only. Clearing browser storage, switching browsers, or using a different device will reset all local records. Export or note positions externally as a backup.

Save inline edits promptly. The dashboard refreshes every 60 seconds and rebuilds the DOM. Unsaved changes in inline balance or note fields may be lost on refresh. Click save before the timer resets.

Trade Journal

Manual record of every planned and closed trade

Journal entries track: asset class, symbol or ticker, entry price, position size, signal state at entry, agent consensus, reason, invalidation level, exit price, result, behaviour review, lesson learned, and notes.

Journal data is stored locally in your browser in Private Local Mode. Reports pull from this data — incomplete journal entries produce incomplete reports.

Highest Exit Risk

Held assets only — priority review flag

This box compares current holdings against live signal state and flags the held asset most worth reviewing right now. It surfaces assets that have moved to Sell Risk or experienced high 1hr drawdown since entry.

It only evaluates assets you hold. It does not evaluate or flag assets in the Opportunity Queue.

Reports

Session, weekly, and trade review

Reports summarise daily activity, weekly performance, closed trade reviews, current positions, and behavioural patterns. All data comes from local Trade Journal and Holdings records.

Reports are only as good as the journal. Missing journal entries, unclosed trades, or partially filled fields will produce gaps in report output.

Alerts

Threshold events — prompts to return to Dashboard

Alerts surface Breakout, Watch, Sell Risk, and Volume Spike events as they occur during a session. Treat every alert as a prompt: return to Dashboard, scan the Opportunity Queue, and analyse the flagged asset before acting.

Do not execute from an alert directly. Run the full analysis workflow first.

Market Logs

System telemetry — verification only

Market Logs show timestamped observations from the decision pipeline: what data was fetched, what signals were scored, and what state transitions occurred.

Use logs to verify what the system observed during a session. Do not use the logs page as an alternative execution surface or signal source.

System & Data

Data sources, known limitations, and planned improvements

Data Confidence and Fallback Snapshot

Check the status bar at the start of every session

Crypto Feed — the Crypto Workspace uses a public/free market feed with no paid API key. Data refreshes when the browser can fetch it.

Fallback Snapshot — if a public feed is unavailable, rate-limited, or blocked by CORS, the portal keeps working from a built-in snapshot and shows fallback status.

Stock Data Direction — stock data may remain static or demo until a safe source is added. Stooq is the initial no-paid-API/static data direction. Finnhub and FMP may be evaluated later only through a secure proxy or static snapshot path, never as frontend keys.

When Fallback is active: use ZenCloud for review and planning only. Execution handoff is de-emphasised and live-signal decisions should wait for live data.

Privacy Modes

Public demo is shareable; private local stays in the browser

Public Demo Mode is safe to share. It shows demo market data, fake demo trades, and fake demo positions only. It does not read private local records.

Private Local Mode reads and writes data in the current browser only. Crypto holdings, stock positions, trade records, watchlists, and settings do not sync across users or devices.

GitHub Pages is public. Anything committed to the repo or deployed to GitHub Pages can be viewed by others. Do not commit private balances, trade deals, private signals, account values, API keys, or strategy notes.

Known Limitations

Understand the boundaries before relying on this portal

  • 60-second DOM refresh — the dashboard rebuilds every 60 seconds. Unsaved inline edits to holdings may be overwritten. Save before the next refresh cycle.
  • localStorage only — all holdings, journal, watchlist, and checklist data lives in your current browser. No cross-device sync, no cloud backup. Clearing browser data resets everything.
  • No paid API required now — crypto uses public/free data, and stocks may remain static or demo until a safe source is added.
  • Stock source direction — Stooq is the initial no-paid-API/static direction. Finnhub and FMP are future secure proxy options only.
  • No API keys in the portal — never paste provider keys or exchange keys into frontend JavaScript, GitHub Pages, localStorage, or repo files.
  • Fallback is review only — fallback keeps Dashboard, Logs, Alerts, Holdings, Journal, Reports, and Guide usable, but it is not live execution context.
  • Responsive tables — compact tables scroll horizontally on small screens to preserve data density.

Static Snapshot Mode

Future reliability path without exposed keys

ZenCloud can later read static JSON market snapshots generated outside the browser. A scheduled GitHub Action or lightweight backend can refresh those files and keep credentials out of GitHub Pages.

This keeps the portal static, avoids paid frontend API dependencies, supports the Stooq no-paid-API direction for stocks, and improves resilience when direct browser fetches are blocked.

CoinSpot API Readiness

Execution boundary remains manual by design

ZenCloud does not use CoinSpot private APIs, exchange keys, or automated order placement. This is a design decision, not a technical limitation.

CoinSpot remains the external venue for manual execution and transaction confirmation. ZenCloud should not store CoinSpot API keys or place orders.

Future Backend Requirements

Required before any key-dependent data source can be activated

  • Secure key storage outside browser-visible files, repositories, GitHub Pages, and localStorage.
  • CORS-safe static snapshot or proxy endpoint that the portal can call without exposing keys.
  • Response caching to reduce usage and stay within rate limits.
  • Rate-limit handling with automatic provider failover.
  • No private keys in frontend JavaScript, HTML files, GitHub Pages deployments, or localStorage.

Safety Rules and Disclaimer

Decision support only — all trading decisions remain the user's responsibility

  • ZenCloud is for scanning opportunities, analysing assets, creating trade plans, checking position size, monitoring exit risk, updating holdings, journaling trades, and reviewing performance.
  • CoinSpot is for crypto execution and transaction confirmation after ZenCloud planning.
  • The stock broker surface is a placeholder only. ZenCloud does not connect to a broker or provide broker execution links.
  • ZenCloud does not execute trades, automate orders, or handle exchange API keys.
  • Signal states (Breakout, Watch, Sell Risk, Volume Spike, No Action) are outputs of deterministic rules applied to available market data. They are workflow states, not instructions to trade.
  • All external trade decisions, risk management, and compliance obligations remain at the user's discretion and responsibility.
  • This tool is an educational and personal workflow aid. Past signal states do not predict future price movement.
