Operator Guide

ZenCloud is a manual multi-asset trading operating portal. Use it to plan, record, and review. It does not execute trades, connect to brokers, or provide financial advice.

If the idea did not start in ZenCloud, do not execute it in the broker. ZenCloud decides. The execution venue executes. ZenCloud records and reviews.

1. Start Here

Open the workspace for the session. Use Crypto Workspace for crypto assets and Stocks Workspace for stocks. The two workspaces are separate — they do not share queues, holdings, or positions.

Check the data status bar at the top of the workspace before anything else. If it shows Fallback or Demo, use the portal for review and planning only. Do not make live-signal decisions until the status shows Live or Snapshot.

Start every session at the Opportunity Queue or Stock Queue. Do not start from market news, external alerts, or the Logs page.

2. Core Rule

If the idea did not start in ZenCloud, do not execute it in the broker. ZenCloud decides. The execution venue executes. ZenCloud records and reviews.

Every trade starts inside ZenCloud: scan, analyse, plan. The external broker or exchange is for execution only — after the plan is complete and saved.

If you cannot articulate the trade in ZenCloud's plan fields — signal state, reason, entry trigger, invalidation level, intended size — it is not ready for external execution.

ZenCloud does not guess broker URLs, pre-fill order forms, or open broker interfaces automatically. The execution boundary is always manual.

3. Quick Start Workflow

Run this sequence every session. Do not skip steps.

  1. Choose the workspace: Crypto or Stocks.
  2. Check the data status bar. Confirm Live or Snapshot before acting on signals.
  3. Scan the Opportunity Queue or Stock Queue.
  4. Select one asset and load it into Asset Analysis.
  5. Review Agent Consensus and work through the checklist.
  6. Create a trade plan: signal state, reason, invalidation level, intended size, notes.
  7. Execute externally only after the plan is saved. Crypto: open CoinSpot manually. Stocks: open your broker manually.
  8. Update Holdings or Positions immediately after the external trade confirms.
  9. Journal the trade: asset class, entry, exit (when known), behaviour review, notes.
  10. Review Reports, Logs, and Alerts at end of session.

4. Crypto vs Stocks

The two workspaces use the same planning and journaling model but different data sources, queues, and execution paths.

Journal and Reports are shared across both asset classes. Each record carries assetClass: crypto or assetClass: stock. Use the filter bar on Journal and Reports to view by asset class.

5. Crypto Workspace

Opportunity Queue ranks assets by signal state and momentum. Open it first, every session. Click Analyse to load an asset into Asset Analysis.

Signal states are workflow labels derived from market data — not trade instructions:

Breakout Watch Sell Risk Volume Spike No Action

Best Swing Mover surfaces one candidate with $100M+ volume, positive momentum, and no Sell Risk state. Use it as a starting point — click Analyse before acting on it.

Market Regime summarises broad liquidity, volatility, dominance, and rotation context. Read it for situational awareness. It does not override the queue, a trade plan, or a Sell Risk state.

Market Attention (Trending, Top Gainers, Top Losers, Most Visited, Recently Added) is for asset discovery only. Route anything found here through the Opportunity Queue and Asset Analysis before planning.

Asset Analysis is sticky on desktop — it stays visible while scrolling. Work through it top-to-bottom: signal → Agent Consensus → plan → position size → checklist → handoff. The checklist requires five manual confirmations. The CoinSpot handoff button stays locked until all five complete.

Agent Consensus runs four deterministic checks: Momentum (trend and 1hr/24hr direction), Liquidity ($100M+ suitable, $25M–$100M caution, below $25M avoid), Risk (move magnitude vs risk bands), Portfolio (asset held or not). Each returns Support, Watch, Reject, or Insufficient Data.

Update Holdings immediately after the external trade confirms in CoinSpot. Holdings are stored in this browser only (Private Local Mode).

6. Stocks Workspace

Stock Queue ranks 41 symbols by signal state. The same signal states apply — Breakout, Watch, Sell Risk, Volume Spike, No Action — derived from 1D price change, 5D change, and relative volume.

Use the region filter to narrow the queue: All, Australia, U.S. Tech, U.S. Large Cap, Global ADRs.

The source badge in the status bar shows where queue data comes from: Snapshot (live Stooq data) or Demo (built-in fallback). A staleness warning appears if the snapshot is more than 24 hours old. See Section 9 for how the snapshot works.

Stock Agent Consensus evaluates four dimensions: sector context, market regime, risk state, and momentum. The result is informational — unlike the Crypto Workspace there is no execution checklist gate for stocks.

Stock Risk Panel shows sector, market regime, and risk state for the selected symbol. Use it alongside the trade plan, not instead of it.

After completing the trade plan in ZenCloud, execute in your own broker manually. ZenCloud does not connect to any broker, does not generate broker links, and does not pre-fill order forms.

Update Stock Positions immediately after the external trade confirms. Positions are stored in this browser only (Private Local Mode).

7. Shared Tools

Trade Journal records both crypto and stock trades. Each entry has assetClass set to crypto or stock. Fields include: symbol, entry date/time, entry price, position size, signal state at entry, agent consensus, reason, invalidation level, exit date/time, exit price, exit reason, whether the plan was followed, mistake type, lesson learned, and notes. Use the filter bar (All / Crypto / Stocks) to view records by class.

Reports pull from Journal records only — no live market data. Tabs: Daily, Weekly, Trades, Positions, Behaviour, Consensus Outcomes. Use the asset class filter to isolate crypto or stock performance. Reports are only as accurate as the journal — missing or incomplete entries produce gaps in output.

Watch Queue stores candidates added from Asset Analysis. Each entry records reason watched, signal at watch time, and current signal state. Return to Asset Analysis when signal state improves.

Journal data is stored locally in the current browser when Private Local Mode is active. It does not sync across browsers, devices, or users.

8. Logs and Alerts

Both pages have Crypto and Stocks tab filters. Select the relevant tab for the asset class being reviewed.

Logs show timestamped system observations: what data was fetched, what signals were scored, what state transitions occurred. Use logs to verify what the system observed during a session. The Logs page is a verification surface — not an execution or signal surface.

Alerts surface threshold events — Breakout, Watch, Sell Risk, Volume Spike — as they occur. Treat each alert as a prompt to return to the relevant workspace, open the queue, and load the flagged asset into analysis. Do not act on an alert without running the full analysis workflow first.

9. Data Sources and Fallback

Crypto — the Crypto Workspace fetches from a public/free market API. No paid API key required. If the fetch fails (rate limit, CORS, network issue), the portal switches to a built-in static snapshot and the status bar shows Fallback.

Stocks — Stooq Snapshot — the Stocks Workspace reads from data/stocks-snapshot.json, a file generated by a GitHub Actions workflow. The workflow runs hourly, fetches 41 symbols from the Stooq CSV API (free, no key required), derives signal states from 1D change, 5D change, and relative volume, then writes the snapshot file. The Stocks Workspace fetches this file at page load and uses it to populate the queue.

Demo fallback — if the snapshot file is empty (seed state before the first workflow run), contains no assets, or the fetch fails, the Stocks Workspace switches to a built-in demo dataset. The source badge shows Demo. No real prices are shown in demo mode.

When Fallback or Demo is active: use ZenCloud for review and planning only. Do not make live-signal execution decisions until the status shows Live or Snapshot.

No API keys are stored in GitHub Pages, frontend JavaScript, localStorage, or the repository. The Stooq fetch runs in GitHub Actions only.

10. Privacy and Public Sharing

Public Demo Mode — shows demo market data, demo trades, and demo positions only. It does not read private local records. Safe to share or screen-record.

Private Local Mode — reads and writes data in the current browser via localStorage only. Crypto holdings, stock positions, journal records, watchlists, and settings do not sync across users, browsers, or devices. Clearing browser storage resets all local records.

Hide Values — masks holdings, positions, entry prices, trade amounts, unrealised P/L, and report values across both workspaces. Toggle in Settings or the topbar privacy control. Use this when sharing a screen without sharing financial detail.

GitHub Gist sharing — save a GitHub Personal Access Token (gist scope only) in Settings to share selected journal trades as a secret GitHub Gist. The token is stored in localStorage only and is never committed to the repo.

GitHub Pages is public. Do not commit private balances, API keys, strategy notes, or account values to the repository.

11. Execution Boundaries

ZenCloud does not execute trades, connect to exchange or broker APIs, pre-fill order forms, or generate broker links. These are design boundaries, not technical limitations.
  • Crypto execution — open CoinSpot manually after the 5-check execution gate unlocks in Asset Analysis.
  • Stock execution — after completing the stock trade plan, open your own broker manually. The Broker Handoff panel is a placeholder only.
  • Holdings and positions — update manually in ZenCloud after the external trade confirms.
  • No API keys in the portal — never paste exchange keys, broker keys, or provider keys into frontend JavaScript, HTML, localStorage, or the repository.

12. Troubleshooting

  • Inline edits lost on refresh — the dashboard rebuilds every 60 seconds. Save balance or note edits before the refresh cycle.
  • Records missing after browser change — localStorage is per-browser. Clearing browser data or switching browsers resets all private records. Export critical data externally.
  • Stocks showing Demo — the Stooq snapshot has not been populated yet. The GitHub Actions workflow runs hourly. Trigger it manually via workflow_dispatch in the GitHub Actions tab if you need it immediately.
  • Staleness warning on Stocks — snapshot is more than 24 hours old. Check the workflow run history in GitHub Actions for failures.
  • Crypto status shows Fallback — the public market feed could not be reached. Use ZenCloud for review and planning only until the feed recovers.
  • Icons not rendering — Lucide icons require the CDN script to load. Check network connectivity if icons appear blank.

13. Disclaimer

Signal states (Breakout, Watch, Sell Risk, Volume Spike, No Action) are outputs of deterministic rules applied to available market data. They are workflow labels — not instructions to trade, not price predictions, and not financial advice.

ZenCloud is a personal workflow and planning aid. All trade decisions, position sizing, risk management, and compliance obligations remain the user's sole responsibility. Past signal states do not predict future price movement.

This portal does not connect to financial markets, does not hold funds, does not place orders, and does not provide regulated financial services.

If the idea did not start in ZenCloud, do not execute it in the broker. ZenCloud decides. The execution venue executes. ZenCloud records and reviews.
